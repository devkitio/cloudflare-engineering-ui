# Cloudflare 控制台设计标尺

本参考来自对 Cloudflare 控制台首页、资源列表、资源详情、设置表单、能力受限页与日志壳层的只读抽样观察，用于提炼可迁移的视觉语法，不是 Cloudflare 官方规范。桌面样本以 1920px 为主，并对 1280px、768px、390px 壳层做了抽查；具体项目应以自身品牌、可访问性和现有组件为准。

## 核心气质

1. **功能性安静**：大面积接近白的背景、克制的边界和极少装饰，让注意力留给数据与任务。
2. **工程可信感**：信息命名直接，数字突出，版本、单位、时间范围和状态都靠近数据本体。
3. **分层导航**：全局侧栏负责产品域，顶栏负责上下文与工具，局部页签负责资源视图，内容过滤器负责数据范围。
4. **高密度但不拥挤**：密度来自规则的网格、短标签和稳定行高；大区块之间仍保留 16–32px 的呼吸空间。
5. **品牌色退居签名**：橙色主要出现在品牌标志；操作和图表采用更高辨识度的蓝色。

## 字体与数字层级

| 用途 | 字号/行高 | 字重 | 说明 |
|---|---:|---:|---|
| 命令中心主标题 | 30/36px | 600 | 首页、日志等主任务入口可使用 |
| 标准页面标题、核心 KPI | 24/30px | 600 | 详情或说明型页面；数字可启用等宽数字 |
| 紧凑页面标题 | 20/25px | 600 | 资源列表等已由壳层提供充分上下文的页面 |
| 区块标题 | 16/24px | 600 | 控制数量，不把每张卡都做成大标题 |
| 普通正文、控件 | 14/21px | 400–500 | 默认工作字号 |
| 导航、表头、紧凑行 | 13/16px | 400–500 | 适合侧栏和数据表 |
| KPI 标签、元数据 | 12/16px | 500 | 使用次级色 |
| 徽标、微型辅助信息 | 11/14px | 500 | 仅在不影响可读性时使用 |

- 使用轻微负字距：普通 UI 可从 `-0.01em` 起步；大数字保持自然或略紧。
- 数值使用 `font-variant-numeric: tabular-nums lining-nums;`，单位与数值保持同一基线。
- 版本号、哈希、代码和请求 ID 使用等宽字体；普通标签不要等宽化。
- 中文正文不要小于 13px；低清屏或远距离场景优先 14px。
- 页面标题不是统一 24px：先根据页面职责在 20、24、30px 三档中选择，不要用字号弥补重复标题和冗余说明。

## 间距与尺寸

以 4px 为最小单位，主要节奏为 `4 / 8 / 12 / 16 / 24 / 32`。

- 全局侧栏：桌面端 260px；大多数导航行 32–36px 高。
- 顶部工具栏：58px 高，左右内边距 16px。
- 局部页签：32px 高，水平内边距 10px，6px 圆角。
- 页面内容：桌面端水平内边距 32px，纵向 24px；窄屏降至 16px。
- 普通控件：32–36px 高；主要输入或命令搜索可用 40–44px。
- KPI 卡：桌面端约 200–240px 宽、112–124px 高；同一轨道等宽。
- 图表卡：标题区 48–56px，内容区根据决策密度使用 240–360px 高。
- 表格行：紧凑 36px，普通 44px；可点击行不小于 40px。
- 设置输入：常用 36px 高、8px 圆角；紧凑配置表行可约 38px，但点击目标仍需满足可访问性。

## 壳层与网格

### 桌面端

```text
┌──────── 260px 侧栏 ────────┬──────────── 58px 顶栏 ────────────┐
│ 全局产品域                  │ 面包屑                工具/账户 │
│ 最近访问                    ├─────────────────────────────────┤
│ 分组导航                    │ 资源页签 + 右侧主操作           │
│                             ├─────────────────────────────────┤
│                             │ 过滤器 / KPI / 图表 / 表格      │
└─────────────────────────────┴─────────────────────────────────┘
```

- 侧栏、顶栏、局部页签使用细边界分割，不叠加重阴影。
- 首页内容列可限制在约 1000–1100px 并居中；分析页应充分利用剩余宽度。
- 图表区在 1440px 以上常用两列，列间距 12–16px；需要比较时优先等宽。
- KPI 多于可用宽度时使用横向轨道，不要把卡片压到 160px 以下。

### 资源列表与右侧上下文栏

```text
┌──────── 主列表：资源身份 / 最近变化 / 操作 ────────┬── 使用情况 / 账单 / 账户 ──┐
│ 次行：部署、版本、请求或健康指标                    │ 固定上下文卡片             │
│ 下一资源                                            │                           │
└────────────────────────────────────────────────────┴───────────────────────────┘
```

- 宽屏可采用约 3:1 的主辅比例；1920px 样本中主区约 1245px、右栏约 400px。把这些值视为比例证据，不是跨项目硬编码。
- 右栏只保留持续影响决策的账户级上下文，不重复资源详情，也不与主列表争夺主操作。
- 资源项使用细边界和内部横向分隔形成两层结构；密度来自稳定列线，不靠缩小到不可读字号。

### 资源详情与拓扑首屏

- 顶栏面包屑已经表达资源身份时，不要在正文重复一个巨型标题。
- 局部页签独占一条窄带，主要动作靠右；正文从关系拓扑、流量路径或依赖图直接开始。
- 拓扑之后按“健康 KPI → 当前版本/部署 → 历史或事件”展开；只有关系本身影响判断时才使用图，不为装饰而画图。

### 设置与能力受限页

- 长设置页使用约 800–860px 的表单主列与右侧章节锚点；章节纵向展开，保存动作靠近所属范围。
- 表格、开关、组合框和危险区域可以同页出现，但危险区域必须独立成节并明确后果。
- 能力受限或套餐门槛页使用居中的受限宽度说明布局，标题可用 24/30、600；给出原因、影响和安全下一步，不渲染无意义的空图表。

### 响应式

- `≥ 1280px`：固定 260px 侧栏，数据区域使用剩余宽度。
- `900–1279px`：侧栏可缩窄或折叠为图标导航，图表保持两列直到可读性不足。
- `< 900px`：侧栏进入视口外抽屉；768px 与 390px 壳层样本均未产生整页横向溢出。页签横向滚动，图表单列。
- `< 600px`：内容边距 16px，KPI 横向滚动，表格保留关键列并允许受控横向滚动。

以上窄屏证据只覆盖全局壳层；具体资源页的右栏隐藏、卡片列数和表格策略仍应在目标产品中实测，不把桌面观察外推为事实。

## 边界、阴影与圆角

- 普通卡片以 1px `--cfui-border` 为主；只有需要从同色背景抬起时加 `--cfui-shadow-card`。
- 卡片默认 8px 圆角；分段控制 6px；搜索/命令栏 12px；徽标使用全圆角。
- 面板嵌套时，内层优先用浅灰标题带和分隔线，不再叠一层带阴影卡片。
- 禁止用大量大圆角白卡堆出“模板化 SaaS”观感。

## 深色模式延展

观察页面以浅色为主；深色模式应做语义映射，而不是机械反相：

- 画布约 `oklch(15–18% 0 0)`，表面比画布亮 3–5 个亮度点。
- 主文字约 `oklch(92–95% 0 0)`，次级文字约 `70–75%`。
- 边界使用白色 10–14% 透明度；去除浅色模式的黑色阴影。
- 保留蓝色交互语义，适当提高亮度；状态色必须重新检查对比度。
- 图表网格线比文字更弱，Tooltip 比卡片更亮一级，不使用霓虹光晕。
